# Open-source readiness review (2026-11-01)

An independent read-only review (Codex gpt-5.6-terra) of the whole repository before sharing it and before a public release. Nothing was run; the review read code and configuration. This page records every finding and what was done. Status as of the commit that adds this file.

No secret was found in the tree or in any of the 64 commits at the time (pattern scan for private keys, GitHub, cloud and chat tokens; `npm audit` reports no vulnerabilities in the 2 runtime dependencies).

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | Critical | `setup-control-user.sh` validated the checkout, then copied executable files from that writable checkout to run as `ci-control` next to the GitHub App key (a swap between check and copy). | **Fixed.** The script installs and runs no code any more: it only creates the user and stores the key and ids. The code that runs next to the key is installed by `install-runtime.sh` from verified git objects. |
| 2 | High (reviewer) | The one-time runner credential is in the slot process environment, so the job can read it. | **Accepted, documented** in [SECURITY.md](../SECURITY.md). It is single use, it is the identity of the job's own runner, and it ends with the job. Closing it fully needs the runner and the job steps to run as different users inside the slot. Open item for a later edition. Not verified by a test here. |
| 3 | High | The audit chain uses an unkeyed hash, so a controller that is already compromised can append invented rows. | **Documented limit.** Past rows cannot be edited, deleted or truncated without the independent receiver noticing; false rows appended by a compromised controller cannot be told apart. Keep the anchor off the machine. A signed off-host anchor is an open item. |
| 4 | High | The slot image used a floating `ubuntu:24.04` and unpinned packages. | **Fixed in the Dockerfile** (base pinned by digest, packages from an Ubuntu snapshot id). One deliberate exception: `ca-certificates` is installed first from the live, GPG-signed archive because the snapshot service is https. Built and verified on the farm on 2026-11-01 with `BUILD_IMAGE=1` (pinned image `sha256:602bae96…`). |
| 5 | Medium | The egress filter allowed all IPv6 except private ranges, so a globally routed IPv6 address on a LAN host was reachable. | **Fixed and tested.** All IPv6 from the job user is refused at once (so clients fall back to IPv4). `test/egress-nft.test.ts` loads the real rule file in a throw-away network namespace and fails on the old rules. Host loopback was already unreachable (spike). |
| 6 | Medium | A client with a valid token could hold slow or oversize uploads open. | **Fixed and tested.** Declared oversize bodies are refused before reading, chunked ones stop at the limit, the connection is closed after the 413, and header, request and keep-alive timeouts are set. A connection cap was tried and dropped on review: it would let a few slow sockets lock out every other client. The new test fails on the old code. |
| 7 | Low | Hard-coded GitHub App and installation ids, `/home/...` paths, org and repo names, the runner label and a uid. | **Fixed.** Installers take the ids, paths and the node binary and its hash from the command line (remembered in a root-owned file), the example registry and tests use placeholders, and the live registries stay operator files. the owner's private export tooling builds a clean tree from a commit (refusing symlinks, requiring a private redaction map, searching every file including binaries) and fails if anything of yours is left; images are listed for a human to look at. |
| 8 | Low | No LICENSE or security policy; the design notes list accepted weaknesses. | **Fixed.** Apache-2.0 `LICENSE` and `NOTICE`, `SECURITY.md` with a private reporting route. The design notes keep their limits on purpose: they are the threat model. |

Not checked by the reviewer: live Tailscale access rules, real file and socket modes on a running install, rootless Docker network semantics, GitHub's behaviour when a just-in-time credential is replayed, image provenance, dependency CVEs beyond `npm audit`.

Confirmed fine by the reviewer: the API's prepared SQLite queries, static file mapping, bearer-token hashing, Host and Origin checks, CORS, the TOTP replay and lockout transaction, approval binding, Docker argument construction, and dashboard output escaping.
